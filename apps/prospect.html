How it works

The data

Everything here is read from Odoo at load, through its own JSON-2 API as the key's user, so Odoo's record rules apply. Nothing is copied into the appliance: deals (crm.lead), partners (res.partner), unpaid posted customer invoices (account.move), calendar meetings and chatter are realm-odoo's types OdooLead, OdooCustomer, OdooInvoice, OdooMeeting and OdooMessage. Reads are cached: partners for 15 minutes, deals, invoices, meetings and chatter for 5. A figure that differs from Odoo inside that window is the cache. Money is in each row's own currency, in major units. Firmographics and news appear only when realm-odoo-enrichment is installed.

The questions

OdooPipelineReceivables (the cards): every active deal at the chosen stage, with what its customer still owes. Parameters: stage (default 'Proposition', the stage's exact name), limit (default 50 rows).

MATCH (q:OdooStagePipeline {stage: $stage})-[:HAS_LEAD]->(l:OdooLead)-[:LEAD_OF]->(c:OdooCustomer)
OPTIONAL MATCH (c)-[:HAS_UNPAID_INVOICE]->(i:OdooInvoice)
RETURN c.id                 AS customerId,
       c.name               AS customer,
       c.email              AS email,
       l.id                 AS leadId,
       l.name               AS opportunity,
       l.expected_revenue   AS expectedRevenue,
       l.currency           AS currency,
       l.probabilityPercent AS probabilityPercent,
       i.id                 AS invoiceId,
       i.name               AS invoice,
       i.amount_residual    AS owed,
       i.currency           AS owedCurrency,
       i.invoice_date_due   AS due
ORDER BY customer, owed DESC
LIMIT $limit

OdooDealTriage (the pills on each deal): the largest open deals, each labelled by a model. strategic: large value or a major company; at_risk: the chatter or the odds say it is stalling, whatever its size; standard: everything else. Sentiment is positive, neutral or negative from the deal's own chatter, and empty when nobody has written on it. Parameters: triage (default empty, every label), limit (default 50).

MATCH (b:OdooBook)-[:HAS_OPEN_LEAD]->(l:OdooLead)
WITH l ORDER BY l.expected_revenue DESC LIMIT $limit
MATCH (l)-[:LEAD_OF]->(c:OdooCustomer)
OPTIONAL MATCH (l)-[:HAS_MESSAGE]->(msg:OdooMessage)
WITH l, c, collect(DISTINCT msg.body) AS bodies
OPTIONAL MATCH (c)-[:HAS_DIFFBOT_ORG]->(d:DiffbotOrganization)
WITH l, c, bodies, d,
     CASE WHEN size(bodies) = 0 THEN ''
          ELSE reduce(s = '', x IN bodies[0..6] | s + ' | ' + coalesce(x,'')) END AS thread
WITH l, c, d, thread,
     classify(l.name + ' — ' + c.name +
       CASE WHEN d IS NULL THEN ''
            ELSE ' (' + coalesce(toString(d.nbEmployees),'?') + ' employees)' END +
       ', $' + coalesce(toString(l.expected_revenue),'?') +
       ' at ' + coalesce(toString(l.probabilityPercent),'?') + '% win probability' +
       CASE WHEN thread = '' THEN ' | no recent interactions'
            ELSE ' | thread: ' + thread END,
       'strategic,standard,at_risk',
       'One open sales opportunity. strategic: large value or a major company, worth leadership attention. at_risk: the interactions or odds say it is stalling or souring, whatever its size. standard: everything else.') AS triage
WHERE $triage = '' OR triage = $triage
RETURN l.id AS leadId, l.name AS deal, c.id AS customerId, c.name AS customer,
       l.expected_revenue AS revenue, l.currency AS currency, l.probabilityPercent AS probabilityPercent,
       toInteger(d.nbEmployees) AS headcount,
       classify(thread, 'positive,neutral,negative',
         'Each item is the recent chatter on one sales opportunity. Judge the current disposition of the customer toward the deal from what was actually written.') AS sentiment,
       triage
ORDER BY revenue DESC

OdooMeetingBriefing (the briefings strip): each upcoming meeting, with what the attendee owes, their open deals and a short briefing a model writes from those facts only. Parameter: customer (default empty, every upcoming meeting).

MATCH (b:OdooBook)-[:HAS_MEETING]->(m:OdooMeeting)-[:MEETING_WITH]->(c:OdooCustomer)
WHERE m.start >= toString(date()) AND ($customer = '' OR c.name = $customer)
OPTIONAL MATCH (c)-[:HAS_UNPAID_INVOICE]->(i:OdooInvoice)
WITH b, m, c, count(DISTINCT i) AS unpaid, coalesce(sum(i.amount_residual),0) AS owed
OPTIONAL MATCH (c)-[:HAS_OPPORTUNITY]->(l:OdooLead) WHERE l.won_status = 'pending'
OPTIONAL MATCH (l)-[:HAS_MESSAGE]->(msg:OdooMessage)
WITH m, c, unpaid, owed, l, collect(DISTINCT msg.body) AS bodies
WITH m, c, unpaid, owed,
     collect(DISTINCT CASE WHEN l IS NULL THEN NULL ELSE
       'open deal "' + l.name + '": $' + coalesce(toString(l.expected_revenue),'?') +
       ' at ' + coalesce(toString(l.probabilityPercent),'?') + '% win probability' +
       CASE WHEN size(bodies) > 0
            THEN ' -- thread: ' + reduce(s = '', x IN bodies[0..4] | s + ' | ' + coalesce(x,''))
            ELSE ' -- no recent thread' END
     END) AS dealFacts
OPTIONAL MATCH (c)-[:HAS_DIFFBOT_ORG]->(d:DiffbotOrganization)
OPTIONAL MATCH (c)-[:HAS_NEWS]->(n:NewsItem)
WITH m, c, unpaid, owed, dealFacts, d,
     collect(DISTINCT CASE WHEN d IS NULL THEN NULL ELSE n.title END)[0..3] AS headlines
WITH m, c, unpaid, owed,
     'Meeting: ' + m.name + ' on ' + m.start + ' with ' + c.name + '. ' +
     CASE WHEN owed > 0 THEN 'They owe us $' + toString(owed) + ' across ' + toString(unpaid) + ' unpaid invoice(s). '
          ELSE 'They have no unpaid invoices. ' END +
     CASE WHEN size(dealFacts) = 0 THEN 'No open deals. ' ELSE reduce(s = '', f IN dealFacts | s + f + ' ') END +
     CASE WHEN d IS NULL THEN 'No firmographics resolved for this customer. '
          ELSE 'Company: ' + coalesce(toString(d.nbEmployees),'?') + ' employees' +
               coalesce(', ultimately owned by ' + d.ultimateParentName, '') + '. ' END +
     CASE WHEN size(headlines) = 0 THEN 'No recent news found.'
          ELSE 'Recent news: ' + reduce(s = '', h IN headlines | s + coalesce(h,'') + '; ') END
     AS factText
RETURN m.id AS meetingId, m.name AS meeting, m.start AS starts,
       c.id AS customerId, c.name AS customer, owed, unpaid AS unpaidInvoices,
       synthesize(factText, 'a meeting briefing for the salesperson attending: 4-6 sentences of plain prose, using ONLY these facts, never inventing or softening; if news is present mention the most relevant item; end with the one thing to raise') AS briefing
ORDER BY starts

When it looks wrong

  • "No open opportunities at …": no active deal sits at that stage. Stage names are each business's own; pick another.
  • A deal with no invoice beside it: its customer owes nothing that is posted and unpaid. Paid and draft invoices are not shown.
  • No briefings strip: no meeting starts today or later (the appliance's date, UTC).
  • No pills: the deal is not among the 50 largest open deals, so it was not triaged.
  • "Could not reach the world": the appliance or Odoo did not answer. The realm's status page says which.

What made this possible

The page asks the world for three views by name at load; there is no backend of its own to deploy. The join from a deal to its customer and to their unpaid invoices is a declared edge, read from Odoo in one batched call per hop rather than one call per deal. The triage and the briefing are classify() and synthesize() inside the same query that fetched the rows, so a label is computed from the deal it sits on, with its rubric shown above.
